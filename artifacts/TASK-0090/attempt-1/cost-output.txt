# Medición de coste: un paquete frente a dos paquetes

Fecha: 2026-11-13. Máquina: macOS local; Node v22.14.0; vitest 5.1.0.

## Comando exacto

El benchmark es un test temporal de Vitest (sin dependencias nuevas) conservado
como fuente en `artifacts/TASK-0090/attempt-1/cost-bench.test.ts.txt`:

```sh
cp artifacts/TASK-0090/attempt-1/cost-bench.test.ts.txt tests/unit/game/attack-cost.tmp.test.ts
pnpm exec vitest run tests/unit/game/attack-cost.tmp.test.ts --reporter=verbose
rm tests/unit/game/attack-cost.tmp.test.ts
```

Semilla: **1017**. Calentamiento: 10.000 ataques por arma. Repeticiones: **5**.
Iteraciones por repetición: **50.000**. Se encadena `resolveAttack` real con
`resolvePackets` sobre un objetivo con defensa 0 y PV/acciones altos para medir
el ataque completo (impacto, paquetes y reacción del enemigo). Armas elegidas del
catálogo: `sword` (1 paquete) y `electric-sword` (2 paquetes).

## Lectura

- Media por ataque: 0,549 µs con un paquete y 0,752 µs con dos.
- Coste adicional de dos paquetes: **0,203 µs por ataque** (×1,37).
- Presupuesto de 60 fps: 16,667 ms por fotograma; caben ~30.300 ataques de un
  paquete o ~22.200 de dos por fotograma. El coste del resolvedor es
  despreciable frente al render y no degrada el objetivo de 60 fps.
- Un ataque de dos paquetes consume como máximo 2 tiradas de ataque/escudo más
  2 de daño y 2 de resistencia; el benchmark verifica el impacto en cada
  iteración y el test de matriz lo comprueba por arma del catálogo.
